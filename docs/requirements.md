# 一期需求基线

版本：1.1 · 日期：2026-09-23 · 状态：设计基线，尚未实施。

来源为用户提供的《日立电梯 AI 翻译业务方案》V1.1 及后续范围调整。此次用户指令优先于原业务方案：**文件翻译暂缓；一期建设完整后端翻译 Agent，通过对话使用；初定 Hy-MT2-7B＋已有 Qwen 3.5。** 技术实现见[技术方案](technical-design.md)，规范性契约见[Spec](spec.md)，硬件估算见[模型部署要求](model-deployment.md)。

## 1. 建设目标与范围

核心目标是提高中、英、日六个方向的翻译准确性：减少错译、漏译、无依据增译、专业概念误用和参数关系错误。以维保资料、产品说明、技术通知的纯文本为优先样本；材料来源可以是文档，但一期由用户粘贴文本，不进行文件识别。

| 能力 | 一期交付 |
| --- | --- |
| 后端翻译 Agent | 上下文、知识、初译、程序检查、原文审校、有限修复、人工处理、可恢复执行和审计 |
| 对话使用 | 新建会话、首次翻译、语言/歧义澄清、补充背景、解释、局部重译、反馈、历史查询 |
| 对话入口 | 轻量聊天页和会话 API；显示进度、原译、问题及版本，不建设完整业务工作台 |
| 文本 API | 同步短文本、异步长文本/批量文本；与对话共用内核 |
| 知识治理 | 术语、翻译记忆、规则、人工整理的领域解释；版本快照和审核发布 API |
| 反馈治理 | 本次、个人、项目、企业四种范围；权限与锁定规则不变 |
| 运行保障 | 身份与项目隔离、任务状态、幂等、重试/取消、注册端点回调、质量评测与运维 |
| 模型 | Hy-MT2-7B 初译；现有私有 Qwen 3.5 处理意图/澄清、审校、修复和有依据的解释 |

一期明确不交付：任何文件上传/翻译/解析/回填/下载（含 Word、Excel、PDF、图片、PPT）、OCR、文件对象存储集成、完整知识/模型管理页面、基础模型训练或领域微调。文件能力另立后续阶段，不作为本期里程碑或验收条件。原 Spec 的文件编号保留为延期记录，不重新解释为其他需求。

## 2. 角色与权限

| 角色 | 职责 |
| --- | --- |
| 普通用户 | 授权项目内对话翻译、查看自己的成果、提交反馈和个人偏好 |
| 项目审核人 | 处理待审译文，审核/发布项目知识 |
| 企业内容负责人 | 审核/发布企业知识、锁定关键项、回滚 |
| 系统管理员 | 管理模型、客户端、回调、运维配置；不默认拥有正文阅读权限 |
| API 调用系统 | 授权范围内创建/查询任务和接收事件 |

会话、消息、任务、知识、审阅和事件流均执行身份与项目权限检查。会话绑定项目，不能通过一条消息切换项目或引用其他用户结果。自然语言“确认”不能替代强制人工终审所需的明确动作、身份和版本校验。

## 3. 翻译 Agent 与模型分工

流程：保存不可变原文 → 构建任务上下文 → 固定知识/模型快照 → 消歧与知识装配 → Hy-MT2-7B 初译或合格 TM 复用 → 程序检查＋Qwen 3.5 原文对照审校 → 定向修复/人工待审 → 跨段一致性与结果保存。

- Qwen 3.5 的对话、审校、修复使用独立提示模板、输出协议和调用记录，可共享现有模型端点。
- 对话模型只决定白名单业务意图，翻译与重译必须进入上述内核，不能直接把对话模型生成的译文当正式结果。
- 审校检查主体、动作、否定、条件、先后、参数归属、漏译和增译；每项问题提供原文/译文定位。只给分数不可放行。
- 全部目标片段都需审校，包含 TM 复用。自动修复最多两轮；修复后复查，出现退化保留旧版并待审。
- 高风险内容保留有权限的人工终审；缺上下文时询问用户，不能补造原文。
- 双模型为初定实施组合，效果仍需业务盲评；只在试点质量通过后发布生产 profile。Qwen 不可用不能跳过审校，Hy-MT 不可用不能静默换成对话直接翻译。

## 4. 对话行为

| 用户表达 | 预期行为 |
| --- | --- |
| “把下面内容翻成英文：……” | 精确提取待译原文与语言方向，创建任务，显示阶段，返回通过门槛的译文或待审草稿 |
| “翻译一下”但未给目标语言/原文 | 先澄清，不猜测语言、不创建无目标翻译任务 |
| “这段说的是电梯门机” | 将明确背景关联指定原文；歧义任务按新上下文建立可追踪子任务 |
| “第二段用更正式的表达” | 解析已展示版本中的第二段，按原文局部重译；目标不唯一先问清 |
| “为什么这样翻译？” | 引用真实原文、术语和命中知识解释；无知识依据时明确为译法说明，不伪造模型内部思考 |
| “这个词以后统一用 X” | 询问未明确的作用范围；个人项受锁定约束，公共项只建草稿并经审核 |
| 断线、刷新、重复发送 | 通过消息/运行 ID 恢复同一任务；不会重复生成新任务或丢失已保存结果 |

原文、用户指令和背景分别保存；每次意图提取需引用精确消息片段。不可将模型生成的对话摘要替代原文。会话默认语种/风格可以继承，但有效值须显示；历史提到的某译法不会自动升级为共享术语。用户继续翻译独立材料时创建新 source/translation，不能误拼到上一次原文。

一期事件流以阶段和经检查的结果为主，不把未审校 token 流呈现为最终译文。待审内容明确标记“草稿/需确认”。轻量聊天页提供原译查看、补充信息、按段修订、反馈及授权审阅提交；完整管理工作台延期。

## 5. 三类知识、上下文与版本

| 类别 | 规则 |
| --- | --- |
| 术语 | 概念、定义、语境、标准/禁用译法、允许变体、范围和锁定；先消歧再约束初译和检查 |
| 翻译记忆 | 经人工确认的双语片段；完全匹配且上下文、版本、权限兼容才直接复用；相似只作参考 |
| 规则 | 强制保护、风格、格式、审校和人工门槛；服务端合并，不允许模型改变权限或下限 |
| 领域解释 | 人工整理的纯文本知识及来源定位；辅助理解，不给译文增添原文无据事实 |

先按权限、发布状态、语言和语境筛选。企业强制/锁定优先，允许覆盖的键按“明确本次 → 当前用户个人 → 项目 → 企业默认”选择；同级冲突待确认。机器项目任务默认不使用个人知识，除非明确用户委托。

每个任务冻结知识、个人/本次覆盖、模型和模板版本。重试继续使用同一快照；对话重译默认继承旧快照，显式选择最新版本时创建新快照并报告变化。上下文变化创建新执行及关联依据，不篡改已有成果。术语改变后将受影响 TM 标记待复核，不能批量替换后直接批准。

## 6. 反馈与持续改进

| 范围 | 生效方式 |
| --- | --- |
| 本次 | 显式重译形成新修订，不写共享知识 |
| 个人 | 确认后进入个人层，不覆盖企业锁定项；当前成果仍需重译才能变化 |
| 项目 | 项目审核、发布后对新任务生效 |
| 企业 | 企业审核、影响分析和版本发布后生效 |

AI 只能建议反馈分类。知识草稿、审核、发布、撤回、回滚保留原因、主体、源任务和版本。确认错误进入回归集，但训练/检索/调试数据不能继续作为独立盲测数据。

## 7. 接口与运行要求

主要接口为 `/v1/agent/conversations`、`/v1/agent/messages`、`/v1/agent/runs/{id}` 及其事件/澄清接口；文本接口 `/v1/translations` 和 `/v1/translation-jobs` 保留。完整字段、状态、幂等、事件与错误码以 Spec 第 6、9 节为准。

长文本和对话操作使用持久异步执行，断开 HTTP 不取消任务。短文本同步等待超时附已有任务标识。知识/模型/审核维护先通过鉴权 API 完成。外部回调继续使用登记端点编码、HMAC、去重与退避，不允许消息指定任意 URL。

模型、数据库、队列和对话编排分别限流；Qwen 的所有角色共享现有端点配额，并为审校/修复留出容量。模型输出、检索文本和待译正文均不可触发任意代码、网络工具或知识发布。

## 8. 服务器与部署边界

Hy-MT2-7B 首期建立 BF16 质量基线：独占 24 GB 显存 GPU 可作为低并发起步档；建议新增采购评估 48 GB 显存 GPU 档。CPU/内存/NVMe 建议及 KV Cache 估算见[模型部署要求](model-deployment.md)。这些是工程预算，不是官方最低配置或已压测吞吐承诺。

Qwen 3.5 复用用户现有服务，不重复采购其 GPU；需要登记具体型号、端点、精度、上下文/输出限制、结构化输出和思考模式配置、可分配并发。不能从“Qwen 3.5 已有”推断其型号或空闲容量。应用后端可用 CPU 服务器，和 GPU 服务通过内网通信。

## 9. 验收目标

一期验收为后端完整翻译闭环＋可实际使用的对话入口，含首次翻译、补充上下文、解释、局部重译、反馈、待审恢复、断线重连与权限隔离；**文件翻译不是一期完成条件**。

准确性按六方向和业务场景盲评：严重/实质错误、漏译/增译、术语误用、必要人工修改、审校召回/误报及修复净收益。Hy-MT 单模型、Qwen 单模型及组合用同一数据对照。初轮 300–500 条可用于筛选，最终规模由覆盖与统计区间确定。

原方案术语正确率 ≥99% 作为参考目标；不代表全文准确率。短文本 P95 5 秒和可用性 99.9% 为待压测目标，不通过减少审校兑现。硬性保护、隔离、严重错误回归、模型发布与自动覆盖门槛见技术方案第 12 节及 Spec 第 11 节。

## 10. 部署前输入

待取得：Hy-MT 服务器资源和检查点版本；现有 Qwen 3.5 接入参数与配额；权威术语及标注语料；审阅负责人；身份系统和网络；保留周期；分方向质量门槛。上述参数不阻塞文档与适配器开发，但对应能力上线前必须登记。此次调整仅更新设计，不表示已连接用户模型或已部署 Agent。
