## 2. 持久化与执行取舍

当前采用模块化单体。Job、Segment、Message、Event、Work、Idempotency、ModelCall、Budget、ModelSlot 为独立类型表；source/snapshot/profile/knowledge/candidate/result/decision/audit 等版本对象使用带类型、租户、项目、owner 和乐观锁的 `records` JSON 聚合表。

这是 Spec 逻辑实体的初始物理映射，不是已完成的全部关系模型。业务服务只追加原文、快照、候选与结果；知识内容通过新版本更新。数据库当前没有对不可变记录实施触发器级防篡改，也没有完整对象外键和每个知识逻辑版本的数据库唯一约束。普通用户只能通过授权 API 操作，生产完整性强化仍待完成。

任务业务状态是恢复依据，LangGraph 检查点保存流程轨迹；重启后安全重放节点，并复用已确认成功的调用。外部模型调用无法做到网络意义上的 exactly-once；未确认结果记录 `outcome_unknown`，累计消耗预算。业务落库用租约、状态和版本检查防止迟到结果越过取消/人工暂停。

当前分段采用保留原始偏移的标点/空白边界，长不可切分 token 保持完整，实际 tokenizer 超预算时失败。相邻原文只作为背景，不并入待翻译内容。跨段一致性目前整批送审；超过 Qwen 实际窗口时拒绝发布，尚无适应超长输入的分层审校器。

验证的代码提交为 [`31c4332`](https://github.com/xzhencheng/aifanyi/commit/31c4332915fc5a2930dbca86380881735a2b1298)，[GitHub CI](https://github.com/xzhencheng/aifanyi/actions/runs/35818029044) 三个作业均成功。PostgreSQL 首轮迁移比较发现 LangGraph 自管表被误判为待删除对象，已划分迁移管理范围并增加回归测试；其他业务 schema 差异仍会报错。

自动化测试覆盖：

- 六个方向进入相同审校路径、同方向拒绝；这**不等于**六方向翻译质量已验收。
- 遗漏审校 ID、伪造 quote、审校不可用、输出截断、思考标签、非法 JSON、空内容均不产生正式结果。
- 数字不一致、单位与数值错配、两轮修复后仍有问题必须待审；高风险需人工确认。
- 修复引入新严重问题时回退；人工修改产生新候选并重新审校。
- 局部重译保留原文及旧结果，未选片段沿用候选但重新检查。
- 同一消息去重、会话忙保护、缺信息澄清、取消后不重启、SSE 最终事件及历史。
- 相同幂等请求共享同一任务，同步等待超时不重建任务；模型调用缓存与预算跨恢复保留。
- 企业锁定术语优先于个人项，可信 TM 复用仍需审校；同优先级冲突不猜测；回滚不改变旧快照。
- 回调签名绑定原始字节，连接固定到已审核 IP 并保留 TLS 主机名；停用回调不发送且不改变已成功翻译。
- 未完成的质量报告不能发布模型组合，非授权/跨项目请求受阻，文件入口未实现且文件输入被拒绝。

上游 Starlette TestClient / AnyIO 有一条弃用告警，不影响本次通过结果。

## 4. 尚未完成的 Spec 项

以下不能用“已有接口”视为完成：

1. **M0 / EVAL-01 / FR-12**：真实模型能力与资源探测、业务语料整理、来源级去重分集、E0–E4 执行器、独立盲评、逐方向错误统计与置信区间、修复净收益和检索污染检查。`POST /v1/evaluation-reports` 是人工登记外部报告的新增接口；Spec 的 `POST /v1/evaluations` 执行器尚未实现。
2. **CORE-02 / FR-03**：术语概念消歧当前是精确命中和同优先级冲突拦截，未实现产品/适用条件的完整检索与消歧、语义检索、候选 TM 排序及高质量上下文压缩。
3. **FR-02/05 / 超长输入**：尚无 tokenizer 驱动的自适应语义重分段、超长跨段分层一致性审校；本版可能对合法 100000 字输入返回预算错误，不能宣称长文本上限已全覆盖。
4. **GOV-01 / FR-08**：反馈到知识的提炼需人工给出结构化内容；once 反馈尚无一键应用；原文更正的独立流程、术语发布影响分析、TM stale 标记及重验队列、紧急知识撤销均待补。复用时仍会检查当前术语，不直接放行冲突 TM。
5. **AUTH-01 / NFR**：完整组织与租户管理、统一资源权限审计、限流、加密/Secret 轮转流程、持久表不可变约束和完整并发验证未完成。测试不等价于安全审计。
6. **OPS-01**：协调数据保留和清理、审计检索/指标/告警、数据库备份恢复、Celery 崩溃/Redis 丢失/长模型调用的容量与恢复实测、容器镜像 digest 固定和部署扫描尚未完成。
7. **CHAT-02**：现有页面支持修订与确认，误报/可接受 minor 的复杂裁决先用 API；完整浏览器端到端回归、生产 OIDC 登录流程和无障碍验证仍需补齐。
8. **Spec 全量验收**：43 个有效 AC 和全部 NFR 没有完成验收。现有 41 项程序测试与 AC 不是一一对应关系，不报告“41/43 通过率”。
