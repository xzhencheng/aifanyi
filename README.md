# AI 翻译平台

面向企业业务场景的 AI 多语言翻译平台，统一提供文本翻译、翻译知识管理、反馈审核与 Office 文件纯文本翻译能力。

项目仓库：https://github.com/xzhencheng/aifanyi

## 当前状态

项目设计阶段。已建立一期需求基线、准确性优先的技术方案和实施 Spec，尚未实现可运行的前后端、翻译服务或部署配置。本文列出的能力均为规划范围，不代表已经交付。

需求来源：用户提供的《日立电梯 AI 翻译业务方案》V1.1。仓库文档提炼通用产品需求；客户原始方案、真实业务文档与语料由项目外部管理。

## 一期范围

- 中文、英文、日文双向互译，模型服务可替换。
- 独立翻译 Agent、Web 翻译工作台、同步及异步 REST API。
- 术语库、翻译记忆库、翻译规则库及任务级版本快照。
- 本次、个人、项目、企业四类反馈作用范围与审核发布流程。
- `.docx`、`.xlsx` 纯文本提取、翻译、原位回填与结构检查。
- 调用系统清单、签名回调、失败重试、权限隔离和审计。

一期不处理 PDF、图片、扫描件、PPT/PPTX、旧版 `.doc`/`.xls` 及文件中的非支持对象。

## 开发约定

1. 以需求基线、技术方案和 Spec 为实现依据，变更范围或质量门槛时同步更新文档。
2. 技术设计采用 Python/FastAPI、LangGraph、PostgreSQL、Celery/Redis、React 和私有 S3 兼容存储；具体版本在工程初始化时锁定。模型检查点、硬件及生产组合须经评测确定。
3. 模型调用经统一网关；文件解析、知识检索、质检和回调使用清晰接口隔离。
4. 所有任务记录模型、提示模板及知识版本；文件任务创建时固定快照。
5. 密钥、生产配置、上传文件、客户词表及真实翻译结果不得提交版本库。
6. 后续直接在 `main` 分支修改和提交，无需新建分支或 Pull Request；提交前读取最新状态，保留已有修改。

## 首个开发里程碑

先建立业务质量基线，比较专用翻译模型与通用模型，并验证 Qwen 等模型审校的净收益；同步验证 Office 片段提取和回填。

随后打通“原文与上下文 → 领域知识装配 → 初译 → 原文对照审校 → 定向修复/人工审阅 → 结果与审计”的准确性内核。默认 `accuracy_first`，不以任务成功或语言流畅代替语义正确。

目前没有可用的启动命令。工程初始化完成后补充依赖安装、配置、启动和验证说明。
